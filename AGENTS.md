# BidScout: notes for agents

A deal scanner for number8.bid for Shaun and the friends he adds (admin-created accounts). Read `README.md` for how it runs and `PLAN.md` for the decisions behind it.

## Rules

- **Scrape with consideration.** All requests go through `server/transport.ts`: at most `concurrency` in flight (1–4, Settings; Shaun chose 4 on 18 Oct 2026), starts at least 300 ms apart (1.2 s plus jitter when one at a time), dropping to one at a time for the rest of a scan after a slow reply or any 429/503, honouring `Retry-After`, stopping after repeated 429/503 or a challenge page, and never touching `/admin` or `/myaccount`. Photos come only from number8's CloudFront image host, one at a time a second apart, at most 3 per lot. Scheduled scans run every `liveEveryHours` (Settings, default 4) plus a weekly past-sales top-up; never add another schedule, a second transport or a second `RequestGate` without Shaun asking. Shaun has permission from number 8 solutions (17 Oct 2026).
- **Everything is cited.** A value shown to Shaun comes from a stored snapshot and a span of `cleanText()` of one field, or from a raw field of a stored response. Never show a guessed value; missing stays missing. If you change `cleanText`, bump `CLEAN_VERSION`. If you change a parser, bump `PARSER_VERSION`; the worker re-parses stored listings when it starts (`npm run reparse` does it by hand). Old `spec_values` stay; they are immutable. Photo values cite a stored photo and the OCR word boxes; they only fill specs the listing left out, and only values from the current `OCR_VERSION` at 60%+ confidence are used or shown. A photo whose text shows an email or phone number is dropped, never stored. Bump `OCR_VERSION` if you change OCR settings and `SCORE_VERSION` if you change the spec score. The expected final and value index are estimates from past sales: always show how many sales and which kind (same machine, similar, spec score) they came from.
- **No personal data.** Bidder usernames, buyer numbers, emails and mobile numbers are redacted before anything is stored (`server/redact.ts`). The one exception is the group's own members: each user enters their own number8 username and bidder number, raw responses are matched against those before redaction (`server/friends.ts`), and only the matches are stored. Never store or show a stranger's bidder identity. Don't surface staff names or contacts from auction intros.
- **number8.bid is the only site scanned.** Other sites appear as links the user opens, with one exception: the Trade Me prices button (`server/trademe.ts`, `server/tmsearch.ts`). It runs only when an admin has turned it on. It loads Trade Me's own search results page (at most two per lookup) through Parallel, Firecrawl or a plain headless Chromium, in that order (an admin's "Test Parallel" button in Settings also reads one results page through Parallel per press, and stores nothing); Trade Me's robots.txt asks crawlers not to use search pages, and Shaun decided on 18 Oct 2026 to use them for this anyway. Listing pages it reads (web-search fallback, pasted links) are checked against robots.txt first. It keeps only the quoted words around each price. Keep it that way: every Trade Me read starts from one person's button press (the lookup may finish after that request returns while the page polls for it, so Safari's one-minute limit doesn't cut it off), with one exception: automatic prices (`server/autoprice.ts`). Shaun decided on 18 Oct 2026 that every open IT lot may be looked up automatically, through Parallel only (never Chromium or Firecrawl), one lookup at a time with a gap between them, under its own daily limit, off until an admin turns it on, and turning itself off when Trade Me refuses Parallel or lookups keep failing. No other scheduled, background-job or bulk Trade Me reading, no stealth (no fake browser fingerprints, proxy rotation or CAPTCHA solving; if Trade Me blocks it, it stops), and no eBay scraping (eBay's terms forbid it).
- **No scraped data in Git.** Snapshots live in `.data/` and the database. Test fixtures are made-up lots in number8's formats.
- Show dates in New Zealand time. The all-in price is bid × (1 + premium) × (1 + GST), with each rate cited from the auction's payment terms when they have been read; otherwise the GST is labelled "assumed".
- Run `npm run typecheck`, `npm test` and `npm run test:db` before pushing. Check UI changes in a browser.
- **Deploying needs Shaun's go-ahead.** Railway deploys `main` on every push, so merging is deploying. Hosted BidScout needs `DATABASE_URL` referencing Postgres, a volume at `/data`, exactly one replica, and `BIDSCOUT_PASSWORD` until the first admin exists (it becomes the password of admin user `admin`).
- Accounts: no self sign-up. Admins create users in Settings. Passwords are scrypt hashes; sessions are httpOnly cookies stored as SHA-256. Everything under `/api` except health and sign-in needs a session.
